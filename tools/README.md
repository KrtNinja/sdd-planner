# Разработка и проверка sdd-lint

Инструмент предназначен для GigaCode CLI: Qwen3.8-flash-next, GLM-5.3-Flash,
DeepSeek-V4.1-Flash. Требования, генерация и проверки по возможности детерминированы;
ИИ используется там, где требуется рассуждение. Изменение продуктовых скиллов — отдельная задача.

## Команды и целевые версии

Из корня репозитория:

```sh
npm --prefix tools install
npm --prefix tools run gate
npm --prefix tools run metrics:fast
npm --prefix tools run lcov
npm --prefix tools run ub:gate
npm --prefix tools run mutate:survivors -- --run <run-id>
```

`gate` запускает все тесты с V8-покрытием, ESLint, tsc, CRAP, повторы и граф импортов.
`metrics:fast` не заменяет gate: он не снимает покрытие. `lcov` — один процесс,
одна последовательность тестов, без покрытия дочерних процессов; требует Node 22.8+.
Пользовательский минимум — Node 22.5.1; CI запускает тесты на 22.5.1 и актуальном 22.
В облачной среде при добавленном прокси-предупреждении Node используется:

```sh
env -u NODE_OPTIONS -u NODE_USE_ENV_PROXY npm --prefix tools run gate
```

crapper, dryer и mutator работают в CI; версии закреплены SHA в
[quality.yml](../.github/workflows/quality.yml). `ub:gate` требует реальные валидные
`.metrics/crap.edn` и `.metrics/dry.edn`; отсутствие отчёта — ошибка.

## Критерии качества

| Проверка | Требование |
|---|---|
| Все тесты и golden | Все проходят; golden не переснимать ради рефакторинга |
| CRAP и CC по функциям | Строго < 10, включая новые помощники; локальный замер и crapper CI |
| ESLint complexity, max-len, no-nested-ternary | 0 |
| Остальные ESLint warnings | Не хуже baseline и уменьшение относительно исходного плана; это не обещание нуля всех warnings |
| tsc | 0; сохранять `// @ts-check` в рабочих модулях |
| Повторы | Код < 2%, тесты < 10%; одновременно не хуже более строгого baseline |
| dryer | 0 пар со сходством ≥ 0,8 |
| Циклы, побочные эффекты процесса вне входа, лишние экспорты | 0 |
| Mutator | Нет выживших; непокрытые места разбираются отдельно, не считаются убитыми |

Нули CRAP/CC и целевых ESLint-правил проверяет `metrics/quality.mjs` независимо от
устаревшего baseline; нули crapper/dryer — `metrics/ub-gate.mjs`. Минимум полностью
прошедших тестов в обязательной проверке — 359, а не текущий размер набора: при ревью
нужно также сверять отсутствие потерянных тестов с базой PR. Базовые линии не являются
автоматическим разрешением регрессии относительно текущего main.

## Процесс изменения

1. Новая ветка от актуального main после вливания предыдущего шага. Один PR на шаг.
2. До упрощения закрепить старое поведение; у функций с небольшой CC сначала покрытие.
3. Коммит по модулю; в сообщении назначение и фактический результат gate.
   После каждого коммита полный gate; после трёх неудачных gate подряд — остановка и человек.
4. Baseline и golden в шаге 10.5 не менять. В дальнейшем baseline обновляет человек
   осознанным отдельным коммитом; подсказка «стало лучше» сама по себе не разрешение.
5. Не ослаблять правила, не исключать рабочий код из замера, не прятать сложность в помощниках.
6. Ручная проверка замены мутанта — в отдельном worktree; исходное дерево тоже обязано проходить тесты.
7. Человек выполняет ревью и merge. Автоматически PR не вливается.

## Полный мутационный прогон

В Actions → quality → Run workflow выбрать **ветку PR** и **mutate: true**.
Это `workflow_dispatch`: все 12 частей проверяют весь выбранный исходный код с нуля.
Обычный PR-прогон берёт изменённые рабочие файлы; PR только с тестами/документацией
может иметь пустой набор. Зелёный пустой PR-прогон не заменяет полный.

После завершения всех частей:

- Проверить head прогона, точный набор файлов по `mutate.mjs files`, наличие 12 частей
  и сборного `mutate-gate`; число форм сверить с описями закреплённого tree-sitter.
- Проверить SHA-256 исходников, формы, диапазоны, хеши, исходники в снимке и суммы
  `sites = killed + survived + uncovered`. Отчёт от старого head не называть новым.
- Выполнить `mutate:survivors -- --run <run-id>` **без фильтра модулей**. Команде нужен
  авторизованный `gh`. При его отсутствии допустим read-only адаптер, который отдаёт
  исходный лог нужного run, скачанный connector; снимок и результаты не преобразовывать.
- Выживший требует различающего теста либо устранения доказанно эквивалентной конструкции.
  Непокрытое место — отдельный долг/ограничение: покрыть достижимое или доказать конкретную
  недостижимость/ограничение измерителя. Дымовой тест процесса не означает мутационное покрытие.
- После изменения кода **или тестов** повторить весь полный прогон на новом head.
  После документального коммита проверить CI и явно сверить неизменность исходников и тестов.

Снимки mutator не хранятся в git. Доказательства и ссылки на полный run остаются в PR.

## Фактическая архитектура — предложение для согласования закрытия

Это описание текущего поведения; решение считать его конечным контрактом вместо
исходного эскиза fs/git-инъекции **ещё не принято**.

- `run(argv)` возвращает `{ code, chunks }`; `ctx.io` инъецирует вывод и завершение команды.
- Файловая система реальная; тесты используют временные папки. В рабочих scripts
  **27** модулей напрямую импортируют `node:fs` (после выделения `inventory.mjs`).
- `loadFeature` принимает `readFn`/`listFn` для отдельных сценариев, но это не полная
  инъекция файловой системы во всех командах.
- git централизован в `git.mjs`; это обёртка реального git, а не общий инъецируемый интерфейс.
- Парсеры и правила разделены по предметным модулям; перенос в `core/` ранее отложен.
  Вынос текстов в отдельный `texts.mjs` отменён; предел строк соблюдается без `ignoreStrings`.

Предлагаемое решение: принять перечисленный фактический контракт для закрытия этого
рефакторинга; полную fs/git-инъекцию не считать выполненной и не добавлять её в шаг 10.5.
Если человек требует исходный эскиз, план остаётся открытым до отдельной согласованной реализации.
