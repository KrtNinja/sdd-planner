## Что действительно прогнано

[Скрипт](documentation-flow-06.mjs) создаёт три искусственные фичи, вызывает реальные
prompt/ask/gen/approve/gate/questions/trace/scenarios и фиксирует код, размер ответа
и время каждого вызова. [Результаты](documentation-flow-06-results.json) содержат полную
последовательность. Тексты документов заданы fixture, а не написаны целевыми моделями.
Репетиция не является полным пользовательским E2E и не измеряет качество их рассуждений.

```sh
# Из корня репозитория; база в отдельном worktree.
git worktree add --detach /tmp/sdd-base06 b7fcb83
node tools/acceptance/documentation-flow-06.mjs /tmp/sdd-base06 --before
node tools/acceptance/documentation-flow-06.mjs .
```

1. **Простая валидация.** Пустое название не сохраняется; короткий SC в spec и существующий
   валидатор в tech, без ADR. Загружены grill/spec, затем отдельные scenarios/tech и общее review;
   ссылки сформированы скриптом. Approve spec успешен, gate slices открыт. Вводы человека,
   которые предполагает этот маршрут: задача/важное бизнес-решение, запуск следующей цели,
   общее одобрение результата. Новые технические вопросы и отдельные одобрения файлов не нужны.
2. **Экспорт.** Фоновое ожидание, ошибка и повтор; Q исходного grill отложен коллегам.
   Ask показывает ожидание, approve spec возвращает 3. После ответа ask/resume возвращают
   исходную ветку; Q остаётся answered, ответ не подменяет согласованный пакет. Инструкция
   требует проверить уточнения, а не повторить всю беседу. Пользовательские действия по сценарию:
   отложить вопрос, принести ответ, рассмотреть только его последствия. Проведение пакета
   отдельно покрывают прежние registry/decision/tech тесты; репетиция здесь останавливается на обработке.
3. **Сложная фича.** Ранний ADR с основанием SC принят до slices (код 0), затем сценарии
   механически перенесены из spec при превышении READ_LIMIT. Trace использует новые адреса.
   Далее тот же цикл ожидания/ответа Q; зависимое одобрение блокируется. Размер искусственно
   доведён заполнителем до границы: это проверка механики переноса, не образец полезного большого SC.
   Дополнительные решения человека: значимый выбор ADR и выбор переноса; новых ID и одобрений
   сценариев перенос не требует. В реальной работе отдельный вызов ИИ на перенос не нужен.

## Измерения контекста и вызовов

Символы — длина фактически возвращённого текста JS, не токены модели и не READ_LIMIT.
В сумму включены инструкции/карточки и контекст resume, но не скрытый system prompt GigaCode.
Содержательные чтения документов перечислены отдельно в JSON; каждый файл прочитан один раз,
повторных явных чтений в скрипте — 0. Внутренние чтения парсеров не считаются чтениями модели.

| История | Вызовы до → после | Символы выдачи до → после | Детерминированное время, мс до → после |
|---|---:|---:|---:|
| Валидация | 8 → 10 | 68 317 → 79 880 | 104,95 → 67,75 |
| Экспорт | 12 → 14 | 93 023 → 93 778 | 292,89 → 49,44 |
| Сложная | 15 → 17 | 103 510 → 104 428 | 95,66 → 73,12 |

Два добавленных вызова — загрузка отдельных целей scenarios и tech по уточнению владельца,
а не служебные операции, которые аналитик должен вводить вручную. В стандартном вопросе этапа
появляются два перехода; число бизнес-согласований до slices остаётся одним. Это дополнительная
нагрузка на простой путь, а не объявленное сокращение числа действий.

Prompt grill: 22 516 → 12 651 символ, spec: 21 853 → 11 829. Теперь каждый из них решает одну цель.
Суммарная выдача простой репетиции выросла на 16,9%: разделение снижает объём инструкций
одного шага, но не суммарную стоимость. Если продолжать все шаги в одном окне, старый контекст
не исчезнет; существующий выбор новой сессии рекомендуется на границе целей. В новой сессии
достаточно карточки ask и связанных фрагментов; повтор всего реестра не требуется.

Фактических вызовов целевых ИИ — **0**, действий реального пользователя в скрипте — **0**.
Предполагаемых содержательных проходов агента: до — grill/spec/review (3), после —
grill/spec/scenarios/tech/review (5); для ответа Q добавляется обработка исходной ветки.
Это схема работы, не измерение выполненных модельных вызовов. Время модели неизвестно.
Один прогон времени Node не доказывает ускорение; разница зависит от кэшей и нагрузки среды.
