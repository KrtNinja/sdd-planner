# sdd-spec — Dev Spec из протокола

Вход: `docs/<feature>/brainstorming.md` со статусом «готов».
Выход: `docs/<feature>/spec.md` со статусом «на ревью» и таблица трассировки в ответе.

Dev Spec — постоянный источник правды о поведении: по нему режут slices, пишут AC и тесты.
Поэтому в нём только то, что решил человек, и только словами пользователя. Технологии меняются,
поведение остаётся — им место в ADR и контрактах.

## Шаги

1. Прочитай протокол целиком, включая «Вне scope» и «Решения после brainstorming».
   Статус не «готов» — напиши «Сначала закончите `/sdd-grill`» и остановись.
2. Составь таблицу трассировки: каждая строка протокола → `FR-n`, `NFR-n`, «вне scope»
   или «не про поведение» (с причиной).
   Готово, когда у каждой строки протокола есть цель.
   Источник — колонка «Решение». Рекомендация агента не решение: её числа и варианты в FR
   не попадают, даже в примеры. Решение «уточнит продукт» → открытый вопрос.
3. Подбери персонажей и данные для примеров. На каждое правило «можно / нельзя» нужен персонаж
   для обоих исходов: Анна-исполнитель и Вера-не-исполнитель, активный и заблокированный.
   Обычно хватает 4–7 персонажей и 2–4 объектов.
4. Напиши `spec.md` по [assets/spec.md](assets/spec.md):
   - одно правило — один FR; сначала правило, затем «Пример:» с конкретным исходом;
   - тексты сообщений — дословно в кавычках;
   - граничные значения — парой «проходит / не проходит» (2048 и 2049 символов);
   - техническое решение протокола переводи в то, что видит пользователь: «UTF-8 с BOM» →
     «кириллица открывается в Excel без настройки», «очередь и S3» → «ссылка на файл приходит
     в колокольчик».
5. NFR пиши с числом и условием: «p95 ≤ 300 мс в проекте до 500 участников».
6. «Вне scope» — всё, что протокол отложил, и всё, что агент мог бы додумать сам.
7. Чего нет в протоколе, но нужно для правила, — в «Открытые вопросы». Ответ не придумывай:
   его даст человек через `/sdd-decide`.
8. Поставь «Статус: на ревью», запусти `node scripts/sdd-lint.mjs docs/<feature>`, исправь ошибки.
9. Выведи таблицу трассировки и строки:
   «Перед checkpoint 1 можно убрать следы ИИ из прозы: `/humanizer docs/<feature>/spec.md`.
   Ревью: `/sdd-review <feature> spec` в новой сессии.
   Checkpoint 1: проверьте spec.md и поставьте „одобрено <дата>“.» Остановись.

## Пример FR

```
FR-3  Причина передачи обязательна, не длиннее 2048 символов. Пустая причина,
      причина из одних пробелов или длиннее 2048 символов не принимается.
      Пример: Анна выбрала Бориса, причину не заполнила → передать нельзя.
      Причина из 2048 символов принимается, из 2049 — нет.
```
