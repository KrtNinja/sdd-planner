# sdd-decide — решение сверху вниз

Вход: вопрос, решение человека (дословно) и источник: «ревью slices», «JIT, Change tasks-core 003».
Выход: обновлённые протокол, spec.md и slices; список изменений в ответе.

Решение, записанное сразу в AC или в Change, расходится со спекой: через месяц никто не знает,
какой документ прав. Поэтому решение всегда спускается сверху: протокол → FR → AC.

## Шаги

1. Запусти `node scripts/sdd-lint.mjs gate decide docs/<feature>`. Код не 0 — передай человеку строку
   «Скажи человеку» из вывода и остановись.
2. Допиши строку в протокол, раздел «Решения после brainstorming»: `П<n>` (следующий номер),
   когда, вопрос, решение. Старые строки протокола не меняй.
3. Найди затронутые FR в `spec.md`: по ID из вопроса или по ключевым словам.
   - решение уточняет правило — поправь FR и добавь пример с этим решением;
   - решение вводит новое правило — новый FR с номером из `node scripts/sdd-lint.mjs next FR docs/<feature>`;
   - решение закрывает открытый вопрос spec — убери его оттуда.
   В «Трассировка» добавь строку `П<n>` → затронутые FR.
   Технический выбор без изменения поведения не трогает spec — предложи `/sdd-adr` и переходи к шагу 7.
4. Найди slices, у которых затронутый FR стоит в «Основание». В каждом:
   - поправь AC или добавь новый: номер — `node scripts/sdd-lint.mjs next AC docs/<feature> <NNN> [B|F]`,
     в строке AC — «[FR-n]» и «(добавлен после: <источник>)»;
   - в шапку добавь «Изменён после: <источник> <дата>: AC-…»;
   - убери закрытый вопрос из «Открытые вопросы к Dev Spec».
   Новый FR без slice — добавь его в «Основание» подходящего slice. Затем `node scripts/sdd-lint.mjs gen readme docs/<feature>`.
5. Статус одобренного документа, который ты поменял, верни в «на ревью» и скажи об этом:
   одобрение давалось другой версии.
6. Запусти `node scripts/sdd-lint.mjs docs/<feature> --snapshot` и, если репозиторий в git, `node scripts/sdd-lint.mjs diff docs/<feature>`.
   Исправь ошибки.
7. Выведи список изменений: файл → ID → что изменилось. Остановись.
