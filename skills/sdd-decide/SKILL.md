# sdd-decide — решение сверху вниз

Скрипт lint: `node <папка этого скилла>/../sdd-lint/scripts/sdd-lint.mjs`, дальше — `<скрипт>`. Запускай из корня репозитория с доками.

Вход: вопрос, решение человека (дословно) и источник: «ревью slices», «JIT, Change tasks-core 003».
Вместо вопроса может быть номер находки ревью — `R2`: вопрос — её «Что не так», источник —
«ревью <режим> R2». Ответ «да» значит «принять её „Предложение“».
Выход: обновлённые протокол, spec.md и slices; список изменений в ответе.

Решение, записанное сразу в AC или в Change, расходится со спекой: через месяц никто не знает,
какой документ прав. Поэтому решение всегда спускается сверху: протокол → FR → AC.

## Шаги

1. Запусти `<скрипт> gate decide docs/<feature>`. Код не 0 — передай человеку строку
   «Скажи человеку» из вывода и остановись.
2. Пришёл номер находки — найди её в `docs/<feature>/review/*.md`. Нет такой или их несколько —
   покажи найденные и спроси, какую. Решение «да» раскрой текстом «Предложения».
3. Допиши строку в протокол, раздел «Решения после brainstorming»: `П<n>` (следующий номер),
   когда, вопрос, решение. Старые строки протокола не меняй.
4. Найди затронутые FR в `spec.md`: по ID из вопроса или по ключевым словам.
   - решение уточняет правило — поправь FR и добавь пример с этим решением;
   - решение вводит новое правило — новый FR с номером из `<скрипт> next FR docs/<feature>`;
   - решение закрывает открытый вопрос spec — убери его оттуда.
   Под блоком каждого затронутого FR допиши `П<n>` в «Из протокола:», у нового FR — заведи строку.
   Технический выбор без изменения поведения не трогает spec — предложи `/sdd-adr` и переходи к шагу 7.
5. Найди slices, у которых затронутый FR стоит в «Основание». В каждом:
   - поправь AC или добавь новый: номер — `<скрипт> next AC docs/<feature> <NNN> [B|F]`,
     в строке AC — «[FR-n]» и «(добавлен после: <источник>)»;
   - в шапку добавь «Изменён после: <источник> <дата>: AC-…»;
   - убери закрытый вопрос из «Открытые вопросы к Dev Spec».
   Новый FR без slice — добавь его в «Основание» подходящего slice. Затем `<скрипт> gen readme docs/<feature>`.
6. Статус одобренного документа, который ты поменял, верни в «на ревью» и скажи об этом:
   одобрение давалось другой версии.
7. Источник — находка ревью: впиши `П<n>` в её колонку «Решение».
8. Запусти `<скрипт> gen links docs/<feature>`, затем `<скрипт> docs/<feature> --snapshot` и, если репозиторий в git, `<скрипт> diff docs/<feature>`.
   Исправь ошибки.
9. Выведи список изменений: файл → ID → что изменилось. Затем блок «Следующий шаг» из вывода lint дословно — в нём готовые команды со slug фичи. Остановись.
