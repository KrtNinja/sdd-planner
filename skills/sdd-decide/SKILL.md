# sdd-decide — решение сверху вниз

Вход: вопрос, решение человека (дословно) и источник: «ревью slices», «JIT, Change tasks-core 003».
Выход: обновлённые протокол, spec.md и slices; список изменений в ответе.

Решение, записанное сразу в AC или в Change, расходится со спекой: через месяц никто не знает,
какой документ прав. Поэтому решение всегда спускается сверху: протокол → FR → AC.

## Шаги

1. Допиши строку в протокол, раздел «Решения после brainstorming»: когда, вопрос, решение.
2. Найди затронутые FR в `spec.md`: по ID из вопроса или по ключевым словам.
   - решение уточняет правило — поправь FR и добавь пример с этим решением;
   - решение вводит новое правило — новый FR со следующим номером;
   - решение закрывает открытый вопрос spec — убери его оттуда.
   Технический выбор без изменения поведения не трогает spec — предложи `/sdd-adr` и переходи к шагу 6.
3. Найди slices, у которых затронутый FR стоит в «Основание». В каждом:
   - поправь AC или добавь новый со следующим номером и пометкой «(добавлен после: <источник>)»;
   - в шапку добавь «Изменён после: <источник> <дата>: AC-…»;
   - убери закрытый вопрос из «Открытые вопросы к Dev Spec».
   Новый FR без slice — добавь его в «Основание» подходящего slice и в «Покрытие» README.
4. Статус одобренного документа, который ты поменял, верни в «на ревью» и скажи об этом:
   одобрение давалось другой версии.
5. Запусти `node scripts/sdd-lint.mjs docs/<feature>`, исправь ошибки.
6. Выведи список изменений: файл → ID → что изменилось. Остановись.
