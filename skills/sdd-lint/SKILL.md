# sdd-lint — проверка и текущий этап

Lint — инструмент MCP `sdd_lint`: `sdd_lint ["help","gen"]` — это вызов с `{"args": ["help","gen"]}`.
Нет `sdd_lint` или он не отвечает — остановись и задай вопрос из «Если sdd_lint не отвечает» в правилах планирования. Скрипт для вариантов 2 и 3 — `../sdd-lint/scripts/sdd-lint.mjs` от папки этого скилла.

Вход: slug фичи (`comments`), путь (`docs/comments`) или путь к файлу; `@` перед путём (так его
дописывает Tab в GigaCode) скрипт снимает сам. Аргументов нет — `sdd_lint []`: он печатает фичи
с текущим этапом и готовые команды. Выведи это как есть и остановись.

1. Выбери команду по просьбе человека:
   - проверить, где фича — `sdd_lint ["docs/<feature>"]`;
   - после правки в доках — `sdd_lint ["fix","docs/<feature>"]`: номера вместо `FR-?` и `AC-NNN-?`,
     ссылки, README и латиницу в ID ставит скрипт, затем проверки и сверка с git;
   - закончить этап — `sdd_lint ["done","docs/<feature>"]`: fix, статус «на ревью» и вопрос этапа;
   - проверить план нарезки — `sdd_lint ["plan","docs/<feature>"]`;
   - после humanizer — `sdd_lint ["guard","<файл или docs/<feature>>"]`;
   - снимок перед humanizer, если скилл его не снял, — `sdd_lint ["snapshot","<файл>"]`;
   - изменения против git — `sdd_lint ["diff","docs/<feature>"]`;
   - ссылки на строки — «Из протокола:» в spec, «Основание:» и «Проверяет:» в slices — поставить
     или обновить, старые форматы перенести — `sdd_lint ["gen","links","docs/<feature>"]`;
   - закрыть фичу перед merge — это скилл `/sdd-close <feature>`; здесь `sdd_lint ["close","docs/<feature>"]`
     только по прямой просьбе человека, как approve;
   - откуда какое требование — `sdd_lint ["trace","docs/<feature>"]`: решение протокола → FR/NFR;
   - требования для зоны реализации — `sdd_lint ["export","docs/<feature>"]`: JSON со slices,
     сервисами и ссылками `<feature>/<AC-ID>` для тестов; код 3 — ворота build закрыты, причина в JSON;
   - одобрить spec, slices или ADR — `sdd_lint ["approve","spec","docs/<feature>"]` (или `slices`),
     `sdd_lint ["approve","adr","docs/<feature>","NNNN"]`. Только по прямой просьбе человека; отказ
     скрипта передай как есть — статус руками не ставь.
2. Выведи результат как есть: находки, «Как исправить» и строку этапа.
3. Ошибки есть — предложи, каким скиллом их исправить: решения — `/sdd-decide`, остальное — правкой
   файла. После guard с ошибкой — верни защищённые части как были. Остановись.

Другие sdd-скиллы вызывают этот же скрипт через `sdd_lint`. Все команды — `sdd_lint ["help"]`,
одна — `sdd_lint ["help","<команда>"]`. Git hook для коммитов — `scripts/pre-commit` рядом со скриптом.
