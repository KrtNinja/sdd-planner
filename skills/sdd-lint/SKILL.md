# sdd-lint — проверка и текущий этап

Скрипт: инструмент MCP `sdd_lint` этого расширения, аргументы — массивом в `args` (`<скрипт> guard docs/x` → `sdd_lint {"args": ["guard", "docs/x"]}`). Инструмента нет в списке — `node <папка этого скилла>/scripts/sdd-lint.mjs`. Нужен Node 18+.
Вход: slug фичи (`comments`), путь (`docs/comments`) или путь к файлу; `@` перед путём (так его
дописывает Tab в GigaCode) скрипт снимает сам. Аргументов нет — запусти `<скрипт>` без них: он
печатает фичи с текущим этапом и готовые команды. Выведи это как есть и остановись.

1. Выбери команду по просьбе человека и запусти из корня репозитория с доками:
   - проверить, где фича — `<скрипт> docs/<feature>`;
   - после humanizer — `<скрипт> guard <файл или docs/<feature>>`;
   - снимок перед humanizer, если скилл его не снял, — `<скрипт> snapshot <файл>`;
   - изменения против git — `<скрипт> diff docs/<feature>`;
   - ссылки на строки — «Из протокола:» в spec, «Основание:» и «Проверяет:» в slices — поставить
     или обновить, старые форматы перенести — `<скрипт> gen links docs/<feature>`;
   - перед merge убрать протокол и ссылки на него — `<скрипт> close docs/<feature>`. Только по прямой
     просьбе человека, как approve;
   - откуда какое требование — `<скрипт> trace docs/<feature>`: решение протокола → FR/NFR;
   - одобрить spec, slices или ADR — `<скрипт> approve spec|slices docs/<feature>`,
     `<скрипт> approve adr docs/<feature> [NNNN]`. Только по прямой просьбе человека; отказ скрипта
     передай как есть — статус руками не ставь.
2. Выведи результат как есть: находки, «Как исправить» и строку этапа.
3. Ошибки есть — предложи, каким скиллом их исправить: решения — `/sdd-decide`, остальное — правкой
   файла. После guard с ошибкой — верни защищённые части как были. Остановись.

Другие sdd-скиллы вызывают этот же скрипт через `sdd_lint`, а без MCP — от своей папки: `../sdd-lint/scripts/sdd-lint.mjs`.
Все команды — `<скрипт> help`, одна — `<скрипт> help <команда>`. Git hook для коммитов — `scripts/pre-commit` рядом со скриптом.
