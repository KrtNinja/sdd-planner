# Вопросы тестового нового процесса

Применяется только при наличии `<f>/.sdd-flow.json`; файл не создавай. Без него выполняй прежний скилл.
Этот контракт важнее старых указаний «каждую ветку довести до решения» и локальных списков открытых вопросов.

- В каждом содержательном раунде предлагай «Обсудить с коллегами / отложить». Имя коллеги необязательно.
- Впервые возникший нерешённый вопрос сохрани через `questions add` до показа: ID выдаёт инструмент.
  До записи подготовь контекст, исходный этап, тему и точку продолжения. При наличии сохрани родителя
  и предполагаемые уточнения для разных ответов: они не ограничивают дальнейшие вопросы.
- Служебный вызов: `sdd_lint ["questions","add","<f>","<JSON>"]`. JSON содержит `key` (постоянный
  ключ одного действия), `title`, `stage`, `topic`, `context`, `resume`, `impact` (`known` или `unknown`),
  `refs` (массив существующих ID). Необязательно: `parent` (Q), `followup`, `colleagues`.
  Строки — одна строка текста; абзацы контекста передавай одной строкой, не обрезая содержание.
  `known` допустим только после выяснения области и с непустыми refs; иначе явно `unknown`.
- Один ключ используй повторно только для того же действия с теми же данными, в том числе после сбоя.
  При новом действии нужен новый ключ; ключ предыдущего действия хранится в самой записи Q.
- Ответ «уточню у коллег» — `questions defer` с JSON `{"key":"...","id":"Q1"}`. Не записывай его
  как решение в протокол или FR. Отложенный Q не спрашивай заново при каждом вызове.
- Ответ человека — `questions answer` с `key`, `id`, `answer` дословно. Вопрос остаётся «ответ требует
  обработки». Затем `questions resume` с JSON `{"id":"Q1"}` возвращает правила исходной ветки.
  Для многострочного ответа сохраняй переносы в JSON; origin: analyst/colleague/recommendation/unconfirmed.
  Без Q-ID сначала `questions resume` с `{}`: сопоставь по смыслу, при нескольких кандидатах уточни до записи.
  Ответ обычным текстом также обрабатывается через prompt sdd-decide; несколько вопросов предположением не закрывай.
- Явное исключение человеком — `questions exclude` с `key`, `id`, `decision`, `consequences`.
  Это тоже ожидает внесения решения, не закрывает Q. Не заменяй откладывание исключением.
- Уточнение области — `questions scope` с `key`, `id`, `impact`, `refs`. Оно не отвечает на вопрос.
- Сводка: `questions list <f> {}`; для инструмента фильтры `id`, `stage`, `topic`. Человеку показывай
  карточку инструмента без повторения. В новой сессии сначала сводка, затем только выбранная ветка.
- В новых spec, сценариях, tech, ADR и slices вместо самостоятельных вопросов ставь ссылку на Q:
  `[Q1](questions.md#q1)` из spec; из slice — `../questions.md#q1`; из ADR — `../<feature>/questions.md#q1`.
  Текст Q и статус не копируй. Рядом с неопределённостью сохраняй ссылку, не выдумывай поведение.
- Независимость проверяет `questions work` с JSON `{"refs":["FR-2"]}`. Неизвестное влияние блокирует
  утверждение независимости; сначала выясни область. Отсутствие ссылок не является доказательством.
- Для независимого черновика существующей области вызови `gate spec|slices|adr <f> draft:FR-2,SC-2`.
  Сначала загрузи скилл нужного этапа через `prompt`; передай ему тот же `draft:...` и используй его
  в gate вместо обычного вызова. Правь только выбранную область, не ставь протоколу «готов» и не
  согласовывай документы. Черновик не передаётся в разработку. Новая тема без адресов сначала
  обсуждается в grill; если независимость не установлена, это только выяснение области влияния.
- Исходные вопросы grill до завершения обработки остаются в questions.md. В таблице «Решения»
  допускаются только подтверждённые бизнес-решения. Готовность всего обсуждения не подделывай.
- Реестр и его статусы руками не меняй. При ошибке записи остановись; после остановки писателей
  доступен `questions recover <f> {}`. Если проверка не разрешает восстановление, нужна сверка с Git.

## Ответ Q нового процесса

Если приложен контракт реестра: до обычных шагов вызови `questions resume <f> {"id":"Qn"}`.
Ответ без ID — `questions resume <f> {}`; сопоставь смысл, покажи однозначное предложение в обработке,
а при нескольких кандидатах уточни один вопрос до записи. Сохрани ответ через questions answer дословно.
Затем снова resume: продолжи исходную ветку по возвращённым правилам. Пакет подготовь через
questions prepare/accept/apply по контракту возобновления. Старые шаги прямой правки для Q не выполняй.
После close отсутствующий реестр создаёт questions add; не восстанавливай старые Q и протокол из памяти.
