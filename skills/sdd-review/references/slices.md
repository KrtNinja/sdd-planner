# Чеклист: slices

1. **Перенарезка.** Для каждой пары соседних slices проверь склейку: С1 (без соседа нарушается
   безопасность или целостность), С2 (результат не проверить без соседа), С3 (только отказы,
   краевые случаи или NFR к чужому пути), С4 (один экран или обработчик ради одного FR).
   Совпало — находка «склеить NNN и MMM». У каждого slice, кроме 001 и первого поведенческого,
   в «Почему отдельно» есть Р1, Р2 или Р3 с пояснением; нет — находка.
2. **Недонарезка.** Slice с больше чем 10 AC в одной половине, который можно разрезать без С1–С4, —
   замечание.
3. **Покрытие.** lint сверил ID; проверь смысл: каждый FR из «Основание» действительно проверяется
   хотя бы одним AC этого slice.
4. **Наблюдаемость.** Каждый AC описывает то, что видно на границе половины: экран, сообщение,
   ответ по контракту. Моки, стенды, классы, «через сервис X» в AC — находка.
5. **Данные.** AC используют персонажей и объекты из Dev Spec. Данные подобраны так, что
   неправильная реализация провалит проверку.
6. **Новое поведение.** Каждый AC выводится из FR. AC без опоры на FR — блокер: решение должно
   пройти через Dev Spec (`/sdd-decide`).
7. **Зависимости.** Приёмка slice опирается только на то, что даёт он сам и его зависимости.
8. **Границы.** У каждого slice названы соседи и что у них; общие экраны и обработчики описаны
   в «Пересечения» README.
9. **Открытые вопросы.** Перед одобрением во всех slices «Нет.».
10. **Проверка фичи.** Сквозной сценарий README проходит через каждый стык сервисов и каждый FR.
