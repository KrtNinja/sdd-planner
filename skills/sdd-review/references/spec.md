# Чеклист: Dev Spec

1. **Трассировка.** Каждая строка протокола (`brainstorming.md`, включая «после brainstorming»)
   стоит в FR/NFR или во «Вне scope». Решение протокола, потерянное в spec, — блокер.
2. **Нет выдуманного.** Каждое правило FR опирается на решение протокола. Правило без решения —
   блокер, его место в «Открытые вопросы».
3. **Примеры.** У каждого FR есть «Пример:» на персонажах из «Данные для примеров» с конкретным
   исходом. У правил «можно / нельзя» примеры есть для обоих исходов.
4. **Слова пользователя.** Нет технологий, эндпоинтов, таблиц, файлов, имён классов (lint ловит
   часть). Тексты сообщений — дословно в кавычках.
5. **Границы.** Пределы заданы парой «проходит / не проходит». Пустые значения и пробелы решены.
6. **Краевые ситуации.** Повтор действия, два действия одновременно, недоступность источника
   данных, несколько вкладок и устройств — у каждой ситуации есть FR или «вне scope».
7. **Противоречия.** Одна ситуация не получает два разных исхода в разных FR.
8. **NFR.** Каждый NFR с числом и условием объёма.
9. **Открытые вопросы.** Перед одобрением раздел пуст («Нет.»).
