# sdd-review — ревью перед checkpoint

Вход: фича и режим: `spec`, `slices` или `adr` (для adr — номер или «все ADR фичи»).
Выход: таблица находок в ответе. Файлы не меняются.

Ревью идёт в новой сессии, чтобы агент не проверял то, что сам только что написал по памяти.
Правки вносит человек или `/sdd-decide`, поэтому здесь только находки.

## Шаги

1. Запусти `node scripts/sdd-lint.mjs docs/<feature>`. Каждая ошибка — находка «блокер».
2. Открой чеклист режима:
   - `spec` → [references/spec.md](references/spec.md)
   - `slices` → [references/slices.md](references/slices.md)
   - `adr` → [references/adr.md](references/adr.md)
3. Пройди все пункты чеклиста по порядку. Для каждого прочитай нужные файлы целиком.
   Готово, когда у каждого пункта есть отметка «ок» или число находок.
4. Выведи строку пунктов с отметками, например: `1 ок · 2 ок · 3 две находки · 4 ок`.
5. Выведи находки таблицей:

   | # | Важность | Где | Что не так | Пункт | Предложение |
   |---|---|---|---|---|---|

   Важность: «блокер» — нельзя одобрять, «замечание» — можно одобрить и поправить позже.
   «Где» — файл и ID (`slices/003-transfer.md, AC-003-B6`).
6. Напиши итог: «Блокеров: N, замечаний: M. Решения — через `/sdd-decide`, остальное — правкой
   файла.» Остановись.
