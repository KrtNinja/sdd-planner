# sdd-adr — техническое решение до кода

Lint: инструмент MCP `sdd_lint` этого расширения, аргументы скрипта — массивом в `args`: `<скрипт> gate spec docs/x` → `sdd_lint {"args": ["gate", "spec", "docs/x"]}`. Инструмента нет в списке — `node <папка этого скилла>/../sdd-lint/scripts/sdd-lint.mjs`. Дальше — `<скрипт>`. Запускай из корня репозитория с доками.
Фича в аргументах — slug (`comments`) или путь (`docs/comments`, `@docs/comments/` после Tab): это одно и то же, `@` и `docs/` отбрасывай. Фича не указана — запусти `<скрипт>` без аргументов: он покажет фичи и этап каждой; спроси, какую взять.

Вход: фича и тема («доставка событий о передаче»). Темы нет — пройди по spec и slices
и предложи кандидатов списком.
Выход: `docs/adr/NNNN-<slug>.md` со статусом «предложено».

ADR фиксирует решение, которое иначе агент в Change примет молча и по-своему в каждом сервисе.
Но ADR на каждую мелочь — шум, который никто не читает. Поэтому сначала фильтр.

## Шаги

1. Запусти `<скрипт> gate adr docs/<feature>`. Код не 0 — передай человеку строку
   «Скажи человеку» из вывода и остановись.
2. Проверь три условия ADR:
   - **дорого откатить** — смена потребует миграций, переписывания сервисов или инфраструктуры;
   - **удивит без контекста** — читатель кода спросит «почему так?»;
   - **был реальный выбор** — есть хотя бы две рабочие альтернативы.
   Нет хотя бы одного — напиши, какого, и что решение пойдёт в описание PR или через
   `/sdd-decide`. Остановись.
3. Выпиши требования, которые решение обязано выполнить: FR и NFR с ID и одной фразой.
4. Найди факты сам: что уже есть (код, конфиги, другие ADR в `docs/adr/`). Чего найти нельзя —
   в «Не выяснено».
5. Предложи 2–3 варианта. Плюсы и минусы каждого — через ID требований:
   «минус: при падении после коммита событие теряется — NFR-3 не выполняется».
6. Задай выбор как вопрос `grilling`: «❓ Q1 — …», затем «➡️ рекомендация». Жди ответа.
7. Номер ADR — вывод `<скрипт> next adr docs/<feature>`. Напиши ADR по [assets/adr.md](assets/adr.md).
   В «Последствия» перечисли затронутые slices по номерам и что в них меняется.
   Если решение меняет поведение для пользователя, это вопрос к Dev Spec: предложи `/sdd-decide`.
8. Запусти `<скрипт> docs/<feature> --snapshot`, исправь ошибки и предупреждения `AD-*`.
9. Передай человеку блок «Следующий шаг» из вывода lint дословно — в нём готовые команды со slug фичи:
   в нём ревью ADR и команда `approve adr`. Перед «принято» можно убрать следы ИИ из прозы:
   `/humanizer docs/adr/NNNN-<slug>.md`, затем `guard` по этому файлу. Остановись.

Условия из шага 2 взяты из скилла `domain-modeling` Matt Pocock (MIT).
