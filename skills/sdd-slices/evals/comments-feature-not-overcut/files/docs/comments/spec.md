# Комментарии с упоминаниями — Dev Spec

Статус: одобрено 27.10.2026

Протокол: [brainstorming.md](brainstorming.md)

## Цель

- **Что сможет пользователь:** обсуждать задачу прямо в её карточке и звать коллег упоминанием.
- **Как было до фичи:** комментариев в задачах не было.

## Данные для примеров

| Персонаж | Роль | Состояние |
|---|---|---|
| Анна Петрова | разработчик, исполнитель TASK-42 | активна |
| Борис Иванов | разработчик | активен |
| Вера Смирнова | руководитель проекта | активна |
| Глеб Орлов | разработчик | заблокирован |
| Дина Козлова | разработчик другого проекта | активна |

| Объект | Название | Проект | Кто видит |
|---|---|---|---|
| TASK-42 | «Починить вход по SMS» | «Мобильное приложение» | участники проекта |

## Функциональные требования

```
FR-1  Комментировать задачу может любой, кто её видит.
      Пример: Борис открыл TASK-42 и оставил комментарий. Дина TASK-42 не видит
      и комментировать не может; если запрос всё же пришёл → «Нет доступа к задаче».
```

```
FR-2  Текст комментария обязателен, не длиннее 5000 символов. Пустой текст и текст
      из одних пробелов не принимаются.
      Пример: Борис пишет 5000 символов — принимается, 5001 — «Комментарий длиннее 5000 символов».
```

```
FR-3  Комментарии показываются в карточке от старых к новым: автор, время, текст.
      Пример: Анна написала в 10:00, Борис в 10:05 → сначала Анна, потом Борис.
```

```
FR-4  Автор может изменить свой комментарий в течение 15 минут после публикации.
      Потом кнопки «Изменить» нет; если запрос всё же пришёл → «Время на изменение истекло».
      Изменённый комментарий помечен «изменён», пометку видят все, кто видит задачу.
      Пример: Борис правит комментарий через 10 минут — успешно; через 16 — кнопки нет.
```

```
FR-5  Удалить комментарий может автор и руководитель проекта. На месте удалённого
      остаётся «Комментарий удалён». Остальным кнопки «Удалить» нет; запрос →
      «Удалить может автор или руководитель проекта».
      Пример: Вера удаляет комментарий Бориса — успешно. Анна удаляет комментарий
      Бориса → кнопки нет.
```

```
FR-6  Упоминание: после «@» и 2 символов показываются до 10 подсказок — участники,
      которые видят задачу, по алфавиту ФИО. В подсказке имя и должность.
      Пример: «@Бо» → «Борис Иванов, разработчик». «@Б» → подсказок нет.
      При 11 подходящих участниках показываются 10.
```

```
FR-7  Упомянуть можно только того, кто видит задачу. Заблокированных и чужих
      в подсказках нет; введённое вручную «@Дина Козлова» остаётся обычным текстом.
      Пример: Анна вводит «@Гле» → пусто. «@Дин» → пусто.
```

```
FR-8  Упомянутый получает уведомление в колокольчике.
      Пример: Анна пишет «@Борис Иванов посмотри логи» → у Бориса
      «Анна Петрова упомянула вас в TASK-42».
```

```
FR-9  Изменение комментария не присылает повторное уведомление тому, кто уже был
      упомянут; новый упомянутый получает уведомление.
      Пример: Анна добавила в комментарий «@Вера Смирнова» → уведомление только Вере.
```

```
FR-10 Уведомление может прийти с задержкой, но не теряется и не дублируется:
      одно упоминание — одно уведомление. Сбой доставки не мешает опубликовать комментарий.
      Пример: уведомления временно не доставляются, Анна упоминает Бориса →
      комментарий опубликован, Борис получает одно уведомление позже.
```

## Нефункциональные требования

```
NFR-1 Публикация комментария: p95 ≤ 300 мс при 2000 комментариев в задаче.
```

```
NFR-2 Подсказки упоминаний: p95 ≤ 200 мс в проекте до 500 участников.
```

```
NFR-3 Уведомление об упоминании: p95 ≤ 2 с с момента публикации (без учёта сбоев доставки).
```

## Вне scope
- Вложения и форматирование текста в комментариях.
- Реакции и ответы в ветке.
- Email и push-уведомления.
- Появление чужих комментариев без перезагрузки.
