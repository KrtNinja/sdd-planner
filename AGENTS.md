# Правила разработки SDD Planner

Обязательны для агентов, изменяющих этот репозиторий. Это правила разработки,
а не дополнительная инструкция для агента, который составляет требования.

## Цель

Помочь пользователю получить качественный документ требований на flash-моделях
в GigaCode CLI: Qwen3.8-flash-next, GLM-5.3-Flash, DeepSeek-V4.1-Flash.
Путь: идея → бизнес-требования → сценарии пользователя → архитектурное решение
→ разделение на задачи. Простая задача должна оставаться простой.

## При каждом изменении

1. **Понятный язык.** Проверь добавленные и изменённые файлы на англицизмы,
   кальку и технический жаргон. Текст для пользователя должен быть понятен без
   расшифровки. Точные имена команд, файлов и моделей сохраняй.
2. **Бережный расход контекста.** Правила скиллов и инструкции должны помогать
   агенту выполнить текущую задачу. Не дублируй проверки, подсказки и переходы,
   которые уже обеспечивает sdd-lint. Перед добавлением правила проверь, зачем
   оно нужно модели и нельзя ли обойтись без него. Разнос текста по файлам сам
   по себе не уменьшает объём чтения; оценивай весь загружаемый контекст.
3. **Развилки обсуждать.** Если требование непонятно или есть выбор поведения,
   этапов либо устройства инструмента — уточни у разработчика. Не выдумывай
   требования и не добавляй сложность ради предполагаемых будущих нужд.
4. **Рутина — инструменту.** sdd-lint помогает агенту ориентироваться,
   продолжать работу и переключаться между скиллами; выполняет механические
   действия и проверки. ИИ отвечает за содержание и смысл. Не заставляй модель
   помнить и повторять работу инструмента.

Поддержку старых артефактов и их миграцию не разрабатываем.
Порядок разработки и обязательные проверки — в [tools/README.md](tools/README.md).
