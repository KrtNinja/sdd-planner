# 01. Формат нового процесса и адресация

## Задача

Определить минимальный сохраняемый контракт новой фичи, пригодный для коротких запросов и новой сессии. Не реализовывать вопросы и генерацию документов следующих блоков.

## Требования

F-01. Ввести явный сохраняемый признак версии процесса. Отсутствие признака означает старый процесс. Не определять версию по дате, размеру документа или случайному наличию tech.md.
F-02. После финального включения новые фичи получают новый признак при создании. Старые фичи не мигрируют, не получают новые обязательные документы и не ломаются на start/decide/approve/close. До блока 07 использовать новый формат только в явно выбранных тестовых фичах.
F-03. Признак должен переживать sdd-close, клонирование и новую сессию. Место хранения выбрать по существующей архитектуре; не создавать большой общий state-файл без необходимости.
F-04. Ввести стабильные ID вопросов Q и сценариев SC, а также адресуемых шагов сценария. Перестановка и перенос между файлами не меняют ID. Номера назначает инструмент. Учитывать существующую нумерацию Q в grill, не создавать две конкурирующие системы.
F-05. Закрепить компактные схемы questions, сценария и tech в шаблонах/парсерах. Обязательны только поля, необходимые для восстановления и проверки. Необязательные пустые разделы не печатать.
F-06. Определить типизированные ссылки: вопрос → этап/тема/элементы/родитель; сценарий → FR/NFR; tech → сценарии/FR/NFR/ADR/контракты. Обратные связи получать инструментом, а не поддерживать вручную дублирующие таблицы.
F-07. ID уникальны в пределах фичи; ADR сохраняют существующую область ID. При удалении временных вопросов не допускать повторного использования ID при возобновлении работы: сохранить минимальный счётчик/эквивалентный механизм вне удаляемой области.
F-08. Запись и обновление состояния не должны оставлять полузаписанные файлы при сбое. Не вводить новую универсальную транзакционную платформу; использовать минимальный механизм и проверяемое восстановление.

## Приёмка

- Старая фича без версии работает без обязательного tech и нового реестра.
- Новая тестовая фича сохраняет идентичность процесса после close-подобного удаления временных файлов.
- Перестановка сценариев/шагов и перенос файла не ломают адресацию.
- Дубликаты, несуществующие ссылки и циклы родительских вопросов диагностируются.
- Следующий ID не переиспользует удалённый.
- Формат описан компактно; последующим блокам не нужно заново придумывать схему.

## Ориентиры

model.mjs, feature.mjs, start*, sources*, trace*, gen*, read-size.mjs в skills/sdd-lint/scripts/sdd-lint/.
Не менять существующие форматы FR/AC без отдельной доказанной необходимости.
