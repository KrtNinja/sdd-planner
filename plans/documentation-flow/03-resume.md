# 03. Ответ и возобновление обсуждения

## Задача

Вернуть модель в конкретную ветку исходного этапа и безопасно перенести результат в документы.

## Требования

R-01. Поддержать ответ по Q-ID и обычным текстом через существующие точки входа. При явном ID инструмент точно загружает запись и связанные элементы.
R-02. Ответ без ID модель сопоставляет с вопросами по смыслу. Однозначное предложение показать в составе обработки; неоднозначное соответствие уточнить до внесения. Не закрывать несколько вопросов предположением.
R-03. После ответа инструмент определяет исходный этап и передаёт его актуальные правила с сохранённой точкой продолжения. Для вопроса sdd-grill продолжить соответствующую ветку grilling, не запускать заново все решённые темы и стартовый сбор источников.
R-04. Ответ человека сохраняется дословно. Рекомендация ИИ и сообщение коллег не становятся принятым решением без указания аналитика. Уже явно переданное как согласованное решение не требовать подтверждать повторно перед каждой механической операцией.
R-05. Модель проверяет полноту ответа, новые развилки и противоречия ранее принятым решениям. Новые вопросы имеют собственные ID и связь с родителем. Их можно отложить тем же способом.
R-06. Родительский вопрос может закрыться после внесения своего ответа, даже если появились дочерние. Готовность ветки вычисляется по всем оставшимся зависимостям; закрытый родитель не разблокирует их автоматически.
R-07. Продолжение учитывает изменения контекста после откладывания. Если связанный элемент удалён/изменён и ответ перестал подходить, показать конфликт, не применять его к похожему элементу молча.
R-08. Через sdd-decide подготовить связанные изменения: протокол, пока существует; FR/NFR при изменении обязательств; сценарии; tech; затронутые AC/ADR. Техническое уточнение без изменения поведения не должно автоматически менять FR.
R-09. Пользователь видит компактный список «что меняется и почему», существенные компромиссы и оставшиеся вопросы. Существующее согласование использовать для пакета изменений; не делать отдельный вопрос на каждый служебный файл.
R-10. Закрывать Q после внесения решения, структурных проверок и фиксации статусов пересмотра. При прерывании посередине сохранять «ответ требует обработки»; повторный запуск завершает работу без дубликатов протокола/FR/Q.
R-11. После sdd-close можно возобновить новую фичу: создать questions.md при необходимости, использовать новые ID, сохранить версию процесса. Не восстанавливать весь старый протокол автоматически. По запросу дать точный Git-путь/ревизию для прошлого обсуждения.

## Приёмка

Пример: Q о разрешении больших экспортов отложен на grill. После «разрешаем» модель выясняет ожидание, ограничения и сбои, не считает единственный ответ достаточной спецификацией. Дочерние вопросы связаны с исходным; ранее согласованные роли не спрашиваются заново.

Дополнительно проверить: ответ без ID с двумя кандидатами; частичный ответ; противоречие FR; новая сессия; сбой после записи ответа до обновления документов; повторная обработка; ответ после close.
