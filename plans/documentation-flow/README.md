# Развитие документации SDD: задание для агента

Статус: требования к реализации, код не реализован.
Основание: решения пользователя от 04.11.2026.
Проверенная база: 4dab32fdf488e1f589fa811896eb9cce42629631.

## Цель

Аналитик вместе с коллегами готовит понятную бизнесу и дизайнеру документацию, затем использует её для разработки. Инструмент помогает выяснить поведение, проверить реализуемость, отложить неизвестное и продолжить в новой сессии. Простая фича остаётся простой по объёму документов и числу действий.

## Как работать агенту

1. Прочитать этот файл, [общие ограничения](00-contract.md) и только текущий блок целиком.
2. Проверить актуальный main, применимые AGENTS.md и tools/README.md. Исходные ориентиры ниже не заменяют чтение изменяемого кода.
3. Выполнять один блок в отдельной ветке и PR. Следующий блок начинать после merge предыдущего. Не реализовывать будущие блоки «заодно».
4. Изучать только нужные зависимости. У каждого блока свой результат и критерии приёмки. До завершения блоков 01–07 новый процесс не включать для обычных новых фич: незавершённый путь проверять на тестовых фичах.
5. В PR указать выполненные требования по ID, проверки, ограничения и передачу следующему агенту. Не объявлять весь план выполненным по результатам одного блока.
6. Не менять этот план ради упрощения реализации. Существенное противоречие вынести человеку с конкретными вариантами. Локальные технические решения принимать самостоятельно в рамках контракта.

## Уже принятые решения

- Разработка только под GigaCode CLI и Qwen3.8-flash-next, GLM-5.3-Flash, DeepSeek-V4.1-Flash.
- Новый процесс применяется только к новым фичам. Старые остаются на старом процессе.
- Сценарии по умолчанию находятся в spec.md. При превышении существующего лимита чтения сначала вынести их в scenarios.md.
- tech.md обязателен для каждой новой фичи, но может быть очень коротким.
- Все открытые вопросы фичи находятся в questions.md.
- Можно продолжать независимую работу, пока вопросы отложены. Частичную передачу согласованных частей в разработку в этом изменении не вводим.
- Очистка временных материалов выполняется через sdd-close.
- Техническое решение не даёт ИИ права самостоятельно менять обещанное бизнесу поведение.

## Граница этой задачи

Это требования для будущей реализации. Ветка с этим пакетом не меняет продуктовые скиллы, команды и runtime.
Не входят: новый интерфейс вне GigaCode CLI, миграция старых фич, новый движок планирования, общий рефакторинг, автоматическая рассылка коллегам, генерация дизайна, полноценная система управления задачами.
